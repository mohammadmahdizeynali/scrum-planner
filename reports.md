# Reports

> Agent working notes — internal reference, not user-facing product documentation.
> All rendered as in-app pages (never files — owner decision).

## Weekly report (archived at sprint close)

Generated by the sprint-close flow, stored as JSONB snapshot (`weekly_reports.payload`),
rendered read-only. Four sections in order:

1. **Time per area & project** — table: area → project rows (area-level tasks as an
   «وظایف حوزه» row; standalone tasks as «بدون حوزه»): hours, % of week, billable split.
2. **Task-level breakdown** — every task with time in the week: task, area/project, logged,
   estimate, delta; sorted logged desc. (The Tempo-timesheet view.)
3. **Completed tasks** — tasks Closed during the sprint period (by `closed` transition within
   the range — track via status change timestamp **[Proposal: `closed_at` column on tasks,
   set whenever status → Closed]**), grouped by area/project.
4. **Estimate vs actual** — per project: Σ estimates of member tasks vs Σ logged; per-task
   deltas already in §2; summary line with overall accuracy (e.g. «۸۵٪ برآوردها در بازه ±۲۵٪»).

Header: sprint name + range (Jalali), close timestamp, total + billable hours.
Freeze semantics: recomputing is forbidden (EC-3); reopen + re-close regenerates (sprints.md).

## Monthly report (live)

Navigable by Jalali month («مهر ۱۴۰۵» + ‹ › + picker). Computed live from entries whose start
(user TZ) falls in the Jalali month. Sections:

- **Summary cards**: total hours · billable · non-billable · tasks completed in the month.
- **Per area & project table**: same shape as weekly §1, with month totals; per-week columns
  (4–5 weeks) **[Proposal: compact grid with week columns when it fits]**.
- **Task breakdown**: top tasks by logged (expandable to full list).
- **Completed tasks** (by `closed_at` in month, grouped by area).
- **Estimate vs actual** for tasks that had estimates.
- **Week strip**: each overlapping sprint/week → link to its archived weekly report
  (with a «زنده» vs «آرشیو» distinction: live numbers here, frozen snapshot there).

Note: a Jalali month overlaps 4–5 sprint weeks, including boundary weeks that contain days
of two months. The week strip lists weeks with any overlap; their links show full weeks.
Area/project tables use pure month-bucketed entries (not week sums) so boundaries never
double-count.

## Display rules

- Hours decimal Latin digits; percentages Persian; dates Jalali Persian digits.
- Zero/empty month → empty state with the nearest month having data («شهریور داده دارد»).
- Colors: area colors reused consistently in every chart/table.
- No charting library — the time-distribution donut is hand-rolled SVG (stroke-dasharray
  segments), added on owner request: «سهم هر پروژه از کل زمان» on weekly + monthly views.
  Slices = projects (+ «وظایف حوزه» + standalone), colored by project/area color; hover a
  slice or legend row to spotlight it and swap the donut center to that slice's duration.
  Percent labels on slices ≥ 6% (Persian digits). Still no chart lib in package.json.
